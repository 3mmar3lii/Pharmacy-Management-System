دليل المبتدئين: بنية الأقسام (Categories) والأقسام الفرعية (Sub-Categories)

مرحباً بك! في هذا الدليل سنشرح بالتفصيل الممل كيف قمنا ببناء ميزة الأقسام و الأقسام الفرعية في نظام إدارة الصيدلية الخاص بك باستخدام (Node.js و Express و MongoDB).

الفكرة العامة (Architecture):
المشروع مقسم إلى ثلاث طبقات رئيسية (MVC Architecture، بدون طبقة الـ View لأننا نبني API):
  • Models (النماذج): وظيفتها التحدث مع قاعدة البيانات (MongoDB) وتحديد شكل البيانات.
  • Controllers (المتحكمات): تحتوي على المنطق البرمجي (Business Logic) وتنفذ العمليات (إنشاء، قراءة، تحديث، حذف - CRUD).
  • Routes (المسارات): تستقبل الطلبات من المستخدم (مثل الرابط الذي يكتبه في المتصفح أو التطبيق) وتوجهها إلى الـ Controller المناسب.

1. النماذج (Models)

النموذج هو قالب البيانات الخاص بنا. لنرى كيف بنينا نموذج القسم الفرعي SubCategory.js كمثال:

const mongoose = require("mongoose");

const subCategorySchema = new mongoose.Schema({
    nameEn: {
        type: String,
        required: [true, "English name is required"],
        unique: true,
        trim: true,
    },
    // ... نفس الشيء للإسم العربي ...
    category: {
        type: mongoose.Schema.ObjectId,
        ref: "Category",
        required: [true, "SubCategory must belong to a parent category"],
    },
}, { timestamps: true });

const SubCategoryModel = mongoose.model("SubCategory", subCategorySchema);
module.exports = SubCategoryModel;

شرح السطور:

  • mongoose.Schema(...): نقوم بإنشاء هيكل (Schema) يحدد البيانات المسموح إدخالها.
  • nameEn: حقل لاسم القسم بالإنجليزي، نوعه نص (String)، إجباري (required)، وغير مكرر (unique)، ويتم مسح المسافات الزائدة منه (trim).
  • category: هذا هو السطر الأهم! نوعه ObjectId، أي أنه يحمل "رقم تعريفي" (ID) لقسم رئيسي آخر من مجموعة "Category". هذا هو ما يربط القسم الفرعي بالقسم الرئيسي (يسمى Relationships في قواعد البيانات).
  • timestamps: true: يضيف تلقائياً وقت الإنشاء (createdAt) ووقت التحديث (updatedAt).

2. المتحكمات (Controllers)

هنا نكتب الكود الذي يتم تنفيذه عندما يطلب المستخدم إضافة أو جلب بيانات. يوجد 5 وظائف أساسية في كل Controller (إضافة، جلب الكل، جلب عنصر واحد، تعديل، حذف).

مثال: دالة إضافة قسم فرعي (createSubCategory)

exports.createSubCategory = async (req, res, next) => {
    try {
        const { nameEn, nameAr, category } = req.body;
        
        const newSubCategory = await SubCategoryModel.create({
            nameEn,
            nameAr,
            category,
        });

        res.status(201).json({
            status: "success",
            data: { subcategory: newSubCategory },
        });
    } catch (error) {
        next(error); // إرسال الخطأ ليتعامل معه النظام بناءً على برمجتنا
    }
};

شرح السطور:

  • req.body: نستخرج البيانات التي أرسلها المستخدم في جسم الطلب (مثل الاسم المعرب والإنجليزي ورقم القسم الرئيسي).
  • SubCategoryModel.create(...): نطلب من قاعدة البيانات إنشاء وحفظ هذا العنصر الجديد. نستخدم await لأن العملية تستغرق وقتاً (Asynchronous).
  • res.status(201).json(...): نرد على المستخدم برقم 201 (والذي يعني أنه تم الإنشاء بنجاح) ونرسل له البيانات التي تم حفظها.

3. المسارات (Routes)

نستخدم الـ Routes لربط الروابط (URLs) بالدوال الموجودة في الـ Controllers.

const router = express.Router({ mergeParams: true });

router
    .route("/")
    .get(authMiddleware.AuthMiddleware, subCategoryController.getAllSubCategories)
    .post(
        authMiddleware.AuthMiddleware,
        authMiddleware.restirctTo("admin", "pharmacist"),
        subCategoryController.createSubCategory
    );

شرح السطور:

  • mergeParams: true: هذه الخاصية مهمة جداً للأقسام الفرعية! وهي تسمح للمسار بالوصول إلى المعرفات (IDs) الموجودة في المسار الأب (مثل معرف القسم الرئيسي categoryId).
  • .get(...): عندما يزور المستخدم الرابط بطريقة GET (لجلب البيانات).
  • .post(...): عندما يرسل المستخدم بيانات جديدة بطريقة POST (للإضافة).
  • authMiddleware.AuthMiddleware: هذه حماية (Middleware). تتأكد أن المستخدم مسجل الدخول ويمتلك Token صالح قبل أن تسمح له بالمرور.
  • restirctTo("admin", "pharmacist"): حماية إضافية (Role-based access). تمنع أي شخص من الإضافة ما لم يكن "أدمن" أو "صيدلي" (مثلاً الكاشير لن يقدر على حذف أو إضافة قسم).

4. المسارات المتداخلة (Nested Routes)

في الـ categoryRoutes.js أضفنا هذا السطر:

router.use("/:categoryId/subcategories", subCategoryRoutes);

ما فائدته؟
هذا السطر يسمح لنا بعمل رابط متداخل. تخيل لو أن القسم الرئيسي (المسكنات) رقمه `123`. يمكننا الآن الدخول إلى الرابط:
GET /api/v1/categories/123/subcategories
وسيقوم النظام تلقائياً بإرجاع جميع الأقسام الفرعية التابعة للمسكنات فقط، بدلاً من إرجاع كل الأقسام الفرعية في النظام.

الخلاصة:
أنت الآن كمبرمج تملك نظام متكامل (CRUD) للأقسام والأقسام الفرعية. البيانات محمية، الروابط منظمة، وقواعد البيانات مترابطة باستخدام (References).
